# macOS 文件预览权限与无弹窗降级

## Why

ClipClop 预览文件时会读取剪贴板记录中的原始路径，macOS 因而可能反复请求受保护目录权限，打断用户的剪贴流程。本改动让愿意授权的用户通过一次快捷引导长期使用文件预览；未授权用户则始终获得无弹窗、只展示基本信息的稳定体验。

## Capabilities

- id: CAP-1
  intent: macOS 用户可在 Settings 中进入完整磁盘访问设置，并在完成系统授权后主动开启文件预览。
  success: 用户未开启文件预览时，浏览、选择或按预览快捷键处理文件条目均不读取原文件，也不触发系统文件权限弹窗。

- id: CAP-2
  intent: macOS 用户可在快速入门中了解文件预览所需权限，并使用与 Settings 相同的快捷授权入口。
  success: 快速入门允许用户跳过授权并正常完成；跳过后文件条目只展示基本信息。

- id: CAP-3
  intent: 已完成系统授权并主动开启文件预览的用户可继续使用现有文件预览能力。
  success: 启用后，文件条目的显式预览继续调用现有原生预览流程，文本、图片、链接、颜色和代码等非文件类型行为不变。

- id: CAP-4
  intent: 未开启文件预览的用户仍可识别文件条目及其来源。
  success: 文件条目至少展示已有的文件名或地址、来源应用和文件类型；预览操作显示无需读取原文件的说明状态。

## Constraints

- macOS 不允许 ClipClop 自动授予完整磁盘访问；快捷设置只能打开系统设置，最终授权必须由用户手动完成。
- 文件预览采用本地显式开关进行门控，默认关闭；系统授权与应用内开关缺一不可，应用不得通过探测受保护文件来判断授权状态。
- 未开启文件预览时，所有文件内容、文件元数据、缩略图和 Quick Look 路径必须停止访问原文件，不能以失败重试方式触发权限弹窗。
- 权限引导不得阻塞快速入门完成，也不得影响不依赖原文件的剪贴类型。
- 对外文案使用“完整磁盘访问”或“文件预览权限”，不使用“永久提权”；权限由 macOS 管理，用户可随时撤销，应用不能承诺永久有效。
- Windows 行为保持不变。

## Non-goals

- 不自动修改 macOS 隐私设置，不请求管理员密码，不尝试绕过 TCC。
- 不复制或长期缓存原文件内容来规避权限。
- 不新增逐文件或逐目录授权流程，不实现安全作用域书签。
- 不改变自动粘贴所需的辅助功能权限流程。
- 不改变文件历史记录的捕获、删除和保留策略。

## Success signal

在未授权且文件预览开关保持默认关闭的全新安装上，复制来自桌面、文稿或下载目录的文件后，完整执行打开面板、选择条目、查看基本信息和触发预览，全程不出现文件访问权限弹窗；完成系统授权并主动开启后，同一文件可正常预览。

## Assumptions

- “地址”指当前历史记录已保存的文件路径；基本信息不新增需要访问文件系统才能取得的字段。
- 用户完成系统授权后，通过应用内确认动作开启文件预览；ClipClop 不可靠地猜测系统授权状态。
