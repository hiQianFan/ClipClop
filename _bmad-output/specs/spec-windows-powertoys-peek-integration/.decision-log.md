# 决策记录

## 2026-08-30 · 初始规范

- 选择“检测到 PowerToys Peek 才启用 Windows Space”，未安装时恢复禁用行为。
- 不内置 Web 文件查看器，不使用默认应用作为预览 fallback。
- 安装引导放在 Windows General 设置页，不增加 onboarding 弹窗。
- 第一版实时检测两个官方默认路径，不新增持久化设置、路径配置或缓存。
- 第一版仅支持真实文件和当前索引；不生成临时文件，不承诺 CLI 多文件导航。
- Rust 后端是能力与路径校验的唯一事实来源，主面板、Quick 与设置页共用结果。
- 明确拒绝捆绑、复制或从 PowerToys 源码剥离 Peek；用户安装 PowerToys 是 Windows Space 预览的前置条件。
- 未安装时不提供默认应用、内置 Web viewer、QL-Win 或其他 provider 兜底，能力直接缺省。
- 采用 Files 类产品的零配置外部集成模式：已安装即工作，未安装只在设置中提供官方说明；不弹 onboarding、不用重复 toast、不显示不可执行菜单项。
- 不采用 ZoteroQuickLook 的自定义 command/provider 模式，避免把路径配置和第三方兼容变成长期维护面。

自检结论：五项 SPEC 字段完整，4 项能力均包含可测试的 intent 与 success；Windows 条件启用、未安装无副作用、设置引导、macOS 不回归、权限限制、失败不 fallback 及第一版范围均已保留。实施细节与测试矩阵位于 `implementation-details.md`。假设 PowerToys 继续维持 Microsoft 已公开的两个默认路径和 CLI 参数契约；该变化可由 capability 检测安全降级。无阻塞开放问题。
