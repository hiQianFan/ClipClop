# ClipClop 开源就绪审计

审计日期：2026-07-14
范围：仓库文档、工程配置、CI、构建与可观察到的实现；未执行第三方安全审计或双平台完整实机验收。

## 结论

项目已有清晰的产品、设计、架构、隐私与分发材料，代码也具备模块化基础和双平台 CI。它已经适合以“开发中的开源项目”公开协作，但还不适合宣称为可安全分发的稳定桌面产品。最大风险不是文档数量，而是规范与实现曾出现漂移、缺少前端行为测试、Windows 实机证据、签名供应链和真实安全报告渠道。

## P0：公开正式版本前必须完成

| 缺口 | 当前证据 | 完成定义 |
|---|---|---|
| 文档事实一致性 | 当前正式文档已按实现范围收敛 | README、产品、设计、架构、计划、隐私和代码对核心能力无矛盾 |
| 私密安全报告渠道 | `SECURITY.md` 只有明确占位说明 | 启用 GitHub Private Vulnerability Reporting 或填写受控邮箱，并测试可达性 |
| 双平台发行证据 | macOS 仅本地测试构建；Windows 只有工作流配置 | macOS/Windows 干净环境安装、运行、卸载和剪贴板冒烟均有记录 |
| 代码签名与公证 | 文档明确尚未配置 | macOS Developer ID+公证，Windows Authenticode；公开产物验证通过 |
| 前端关键路径测试 | package scripts 无 test | 键盘、选择/分页、错误恢复和设置至少有自动化测试并进入 CI |
| 发布供应链 | bundle workflow 只上传 artifacts | tag 权限、环境审批、最小 secrets 权限、哈希与 GitHub Release 流程落实 |

## P1：开放外部贡献前建议完成

- 配置 issue/bug/feature 与 PR 模板，要求隐私安全影响和验证证据。
- 设置 `CODEOWNERS`、分支保护、必需 CI 和依赖更新工具（Dependabot/Renovate）。
- 明确维护者名单、响应范围、路线图和兼容性承诺。
- 生成第三方依赖/许可证清单，并确认图标、字体、原型素材的再分发权利。
- 给出各平台精确的数据目录、日志位置、卸载残留和权限说明。
- 增加安装后截图/GIF；必须来自当前实现，不能用原型冒充产品截图。
- 对剪贴板、路径打开、WebView IPC/CSP、SQLite 与日志进行针对性威胁建模和安全审计。

## P2：稳定运营阶段

- 建立语义化版本、弃用与数据库迁移兼容政策。
- 增加性能基线（启动、搜索、内存、超大剪贴板）和回归门槛。
- 建立崩溃诊断策略；若未来引入遥测，必须默认边界、同意机制和隐私文档先行。
- 提供本地化策略、社区支持渠道、治理/决策记录和长期维护预期。
- 考虑可复现构建、SBOM、依赖签名验证和 SLSA provenance。

## 已补齐的文档基线

本轮增加了文档索引、贡献指南、安全策略、行为准则、变更日志、测试指南、故障排查、发布清单与本审计，并扩充 README/隐私说明。这些文件建立了流程，但其中标明的占位项和验收项仍需真实组织信息、凭据、平台与 CI 配置才能关闭，不能仅靠文档勾选。
