# ClipClop 交互契约

本文档定义 ClipClop 已有的键盘、焦点和无障碍语义。调整组件实现或迁移到 Bits UI 时，除非产品明确修改交互，否则必须保持这些行为。

## 1. 基本概念

- **DOM 焦点**：浏览器当前接收键盘事件的元素。
- **活动项**：列表中当前选中的记录。复合控件通过 `aria-activedescendant` 表达活动项时，DOM 焦点保留在容器上。
- **触发器**：打开菜单或确认层的按钮。
- **退出一层**：关闭当前最上层状态并返回上一个可操作位置，而不是直接关闭整个窗口。

## 2. 全局约束

1. 键盘操作不得依赖鼠标先点击界面。
2. 焦点必须始终落在可见、可操作的元素上。
3. 关闭临时界面后，焦点返回触发器；触发器已不存在时，返回历史列表。
4. `Escape` 每次只退出一层。已被子组件处理的事件不得被窗口级处理器再次处理。
5. `Command/Ctrl+W` 关闭当前面板，不受面板内焦点位置影响。
6. 选中状态、DOM 焦点和视觉高亮必须一致；仅用颜色表达状态不够。
7. 原生按钮、输入框和选择框保留原生键盘行为。只有复合控件自行管理方向键和焦点。
8. macOS 与 Windows 可以有不同的系统能力，但共同交互使用相同语义；界面文案不把产品能力描述成某个平台专属能力。

### 2.1 文本选择

ClipClop 是桌面命令面板，不是网页文档。标题、列表摘要、设置说明、菜单、状态、发布记录、文件路径、预览元信息和 loading 等静态界面统一使用默认箭头，且不可拖选。

以下区域保留原生文本光标、选择和复制：

- 文本型 `input`、`textarea` 和明确启用的 `contenteditable`；
- 右侧文本或链接正文预览 `.preview-body.text-preview`。

正文白名单不扩展到同一预览中的元信息、路径、颜色值或加载占位。按钮、菜单项和链接仍保留各自的 hover、focus 和点击反馈，但标签文字不可拖选。

## 3. 历史记录

### 3.1 初始焦点

历史视图打开或重新唤起时：

- 有记录：焦点进入历史列表。
- 加载失败且无记录：焦点进入“重试”按钮。
- 空记录：焦点进入空状态锚点。
- 从系统预览返回：焦点回到历史列表。

是否保留上次浏览位置由 `restore_browse_position` 决定，不改变上述焦点规则。

### 3.2 搜索

| 输入 | 结果 |
| --- | --- |
| `/` | 聚焦搜索框 |
| `Command/Ctrl+F` | 聚焦搜索框 |
| 搜索框内 `Escape` | 返回历史列表，不关闭面板 |

搜索框失去焦点后，交互模式恢复为浏览模式。

### 3.3 历史列表

历史列表是单选 `listbox`：

- DOM 焦点停留在列表容器。
- 当前记录通过 `aria-activedescendant` 指向对应 `option`。
- 每个选项提供 `aria-selected`、`aria-posinset` 和 `aria-setsize`。

| 输入 | 结果 |
| --- | --- |
| `ArrowUp` / `ArrowDown` | 选择上一条或下一条；跨页时选择相邻页的首条或末条 |
| `Home` / `End` | 选择当前页第一条或最后一条 |
| `PageUp` / `PageDown` | 切换上一页或下一页 |
| `ArrowLeft` | 收起已展开记录；否则切换上一页 |
| `ArrowRight` | 切换下一页 |
| `1`–`9`、`0` | 选择当前页第 1–10 条记录 |
| `Space` | 使用系统预览查看当前记录 |
| `Enter` | 粘贴当前记录 |
| `Shift+Enter` | 以纯文本粘贴（内容支持时） |
| `Command/Ctrl+Shift+C` | 复制纯文本（内容支持时） |
| `Command/Ctrl+Left/Right` | 切换当前记录内的文件（内容支持时） |
| `Command/Ctrl+Backspace/Delete` | 打开删除确认 |
| `Command/Ctrl+K` | 打开操作菜单 |
| `Shift+F10` | 列表有焦点时打开操作菜单 |
| `Escape` | 关闭面板 |

鼠标单击选择记录，双击粘贴。点击已选中的可展开记录会展开或收起其子项。

### 3.4 多文件导航

多文件预览使用水平 `tablist`，每个文件是一个 `tab`，并采用 roving `tabindex`：只有当前文件可通过 Tab 序列聚焦。

| 输入 | 结果 |
| --- | --- |
| `ArrowLeft` / `ArrowRight` | 选择并聚焦相邻文件 |
| `Home` / `End` | 选择并聚焦第一个或最后一个文件 |
| `Escape` | 返回历史列表 |

切出 `tablist` 后，交互模式恢复为浏览模式。

### 3.5 应用菜单与操作菜单

- 触发器声明 `aria-haspopup="menu"` 和 `aria-expanded`。
- 容器使用 `role="menu"`，操作项使用 `role="menuitem"`。
- 打开后，焦点进入第一个可用菜单项。
- `ArrowUp` / `ArrowDown` 循环移动焦点，`Home` / `End` 移至首项或末项。
- `Escape` 关闭菜单。应用菜单把焦点还给其触发器；操作菜单返回历史列表。
- 指针点击或焦点移出菜单区域时关闭菜单。

### 3.6 删除确认

- 确认层使用 `role="alertdialog"`、`aria-modal="true"` 和可访问名称。
- 打开后焦点进入确认按钮。
- `Tab` / `Shift+Tab` 只在取消和确认按钮之间循环。
- `Escape` 取消删除并把焦点还给触发器；触发器不存在时返回历史列表。

### 3.7 退出优先级

历史视图中的 `Escape` 按以下顺序只处理第一项：

1. 删除确认
2. 操作菜单或应用菜单
3. 搜索模式或多文件导航
4. 历史面板

## 4. 设置

### 4.1 分类导航

设置分类是垂直 `tablist`，内容区是对应的 `tabpanel`。

| 输入 | 结果 |
| --- | --- |
| `ArrowUp` / `ArrowDown` | 循环切换分类并聚焦对应标签 |
| `Home` / `End` | 切换到第一个或最后一个分类 |
| `ArrowRight` | 进入当前分类的第一个可操作控件；没有控件时聚焦标题 |
| `Tab` | 从分类进入当前内容区 |
| 内容区 `ArrowLeft` | 返回当前分类标签 |

以下位置的 `ArrowLeft` 保留给控件自身，不返回导航：文本输入、选择框、文本域、快捷键录制和 `listbox`。

### 4.2 快捷键录制

- 开始录制后，按键事件由录制器独占处理。
- `Escape` 取消录制并清除录制错误。
- 仅接受包含修饰键且不与保留系统快捷键冲突的组合。
- 录制失败必须保留设置页并给出反馈，不保存无效组合。

### 4.3 更新版本列表

版本列表是单选 `listbox`，DOM 焦点停留在容器，当前版本通过 `aria-activedescendant` 表达。

| 输入 | 结果 |
| --- | --- |
| `ArrowUp` / `ArrowDown` | 选择相邻版本 |
| `PageUp` / `PageDown` | 按当前可见行数翻动 |
| `Home` / `End` | 选择第一个或最后一个版本 |

选择变化后，活动版本滚动到最近的可见位置。

### 4.4 保存与关闭

- `Command/Ctrl+S` 保存设置。
- `Escape` 的优先级是：取消快捷键录制、取消清空历史确认、关闭设置。
- 清空历史确认关闭后，焦点返回其触发器。

## 5. 快速入门

### 5.1 步骤导航

- 非原生输入控件中，`ArrowLeft` / `ArrowRight` 切换上一步或下一步。
- 进入练习步骤后，焦点直接进入示例列表。
- 步骤切换由 live region 宣告；除练习步骤外，不强制移动焦点。
- 最后一步按 `Escape` 完成并退出快速入门。
- 单独打开“自动粘贴”引导时，不启用左右方向键切换步骤。

### 5.2 练习列表

练习列表是单选 `listbox`，DOM 焦点保留在容器，当前示例通过 `aria-activedescendant` 表达。

| 输入 | 结果 |
| --- | --- |
| `ArrowUp` / `ArrowDown` | 循环选择示例 |
| `1`–`3` | 快速选择对应示例 |
| `Space` | 平台支持时打开或关闭系统预览 |
| `Enter` | 将示例内容放入练习目标，焦点保留在示例列表 |
| `ArrowLeft` / `ArrowRight` | 交给步骤导航处理 |

系统预览关闭、窗口重新获得焦点后，焦点返回练习列表。离开练习步骤时，已打开的系统预览必须关闭。

### 5.3 语言菜单

- 触发器使用 `aria-haspopup="menu"` 和 `aria-expanded`。
- 选项使用 `role="menuitemradio"` 表达当前语言。
- 触发器按 `ArrowDown` 打开并聚焦当前语言，按 `ArrowUp` 打开并聚焦末项。
- 菜单内 `ArrowUp` / `ArrowDown` 循环移动，`Home` / `End` 移至首项或末项。
- `Escape` 关闭并返回触发器；`Tab` 关闭后继续正常 Tab 顺序。
- 点击菜单外部时关闭菜单。

## 6. ARIA 使用规则

ARIA 用于补充原生 HTML 无法表达的语义，不替代原生行为：

| 控件 | 必需语义 |
| --- | --- |
| 历史、版本、练习列表 | `listbox` + `option` + `aria-selected`；容器用 `aria-activedescendant` 指向活动项 |
| 设置分类 | `tablist` + `tab` + `tabpanel`，并连接 `aria-controls` / `aria-labelledby` |
| 多文件导航 | `tablist` + `tab` + `aria-selected`，采用 roving `tabindex` |
| 菜单 | 触发器 `aria-haspopup` / `aria-expanded`；容器 `menu`；项目 `menuitem` 或 `menuitemradio` |
| 删除确认 | `alertdialog` + `aria-modal` + 可访问名称 |
| 异步预览与加载 | 使用 `aria-live`、`aria-busy` 或 `role="status"` 表达状态 |

不得只添加 ARIA 角色而缺少对应键盘行为和焦点管理。

## 7. Bits UI 迁移边界

迁移按控件逐步进行，不做一次性重写：

1. 优先迁移应用菜单、操作菜单和语言菜单。
2. 设置分类可在确认自定义左右焦点行为不变后迁移。
3. 历史列表、更新版本列表和练习列表保留现有实现；多文件导航使用 Bits UI Tabs，并保留预览加载与 Escape 回退逻辑。
4. 原生按钮、输入框、选择框和开关不迁移。

每个迁移必须同时满足：

- 本文列出的按键结果不变。
- 打开、关闭和操作后的焦点落点不变。
- ARIA 角色、状态和控件关系不弱化。
- macOS 与 Windows 的现有分支不变。
- 原有自动化检查通过，并为迁移控件补上缺失的键盘测试。

## 9. 维护规则

- 改变本文任一行为时，在同一变更中更新文档和对应测试。
- 视觉样式、数据读取、系统权限实现和业务规则不属于本文范围。
- 实现与本文冲突时，先确认这是缺陷还是产品变更；不要静默改变既有交互。
