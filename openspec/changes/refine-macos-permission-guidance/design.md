## Context

当前 PermissionSettings 使用 shouldRestartAfterPermissionCheck 判断权限从 required 变成 ready 后延迟四秒 relaunch；此条件无法覆盖权限查询仍为旧值的情况。授权操作与权限检测结果应分别记录：前者仅说明用户启动过配置流程，后者是当前进程所报告的能力。

## Decisions

### 页面与引导窗口

主设置页仅保留两项权限及简短用途。移除“当前 App”整块；App 路径只用于后端定位真实拖拽对象及诊断，不常驻产品页面。

点击“去授权”打开系统设置辅助功能页及小型非模态引导窗口。窗口不遮挡系统开关，可关闭，只在用户发起配置流程时出现，不在后台持续抢焦点。无需追踪或操纵系统设置窗口来实现伴随布局。

窗口文案：

- 标题：启用自动粘贴
- 说明：在系统设置中开启 ClipClop。
- 拖拽区：列表中没有 ClipClop？将图标拖入列表并开启。
- 重启提示：如果已在系统设置中开启 ClipClop，请重新启动应用。
- 操作：重启应用；稍后。

拖拽必须是当前运行的真实 .app 文件 URL，不能只是网页图片。保留窗口内“在访达中显示”作为不能拖拽的替代方法，并说明系统设置的加号添加路径。开发进程不伪造 .app 拖拽，展示简短的安装版测试说明。

完全磁盘访问窗口使用同样结构，标题“启用文件访问”，说明开启完全磁盘访问；不声明所有文件预览都需要此权限。两个权限可以配置完再由用户重启一次。

### 主操作与展示状态

| 场景 | 右侧主要按钮 | 提示与行为 |
| --- | --- | --- |
| 首次查询中 | 检测中 | 控件宽度稳定 |
| 查询返回 required，未进入授权流程 | 去授权 | 打开设置及引导 |
| 查询返回 ready，未进入授权流程 | 已就绪 | 绿色轻背景，点击仍打开配置引导 |
| 已发起配置并返回 ClipClop | 重启应用 | 条件提示由用户判断；即使查询仍为 required 也可重启 |
| 上一行状态下查询返回 ready | 重启应用 | 本次引导的操作优先，不能因一次查询而移除重启入口 |
| 用户选择稍后/关闭窗口 | 保留页面上的重启应用 | 本进程本次配置会话内可稍后执行；不反复弹窗 |
| 重启后的新进程 | 重新查询后显示去授权或已就绪 | 不继承“需要重启”标记，避免重启循环 |
| 查询失败 | 重新检测（正常状态）或重启应用（配置会话） | 报告检测失败，不伪装成未授权或已就绪 |
| 完全磁盘访问 | 打开设置；配置返回后可重启应用 | 无总权限成功状态 |

“重启应用”采用项目普通操作按钮样式，不沿用表示就绪的绿色。仅“已就绪”使用现有成功绿 token 与绿色 hover。不能保留“已就绪”标签却悄悄把点击行为变成重启。

### 刷新图标

使用现有 RefreshCw 图标，隐藏可见文字，tooltip 和 aria-label 均为“刷新状态”。保持至少 32px 点击区域、键盘焦点与主题对比度。仅手动刷新图标承担忙态；已有状态按钮不因查询反复变宽、变色或闪烁。

进入可见权限页、授权流程返回前台、用户主动点击时查询。合并并发查询，忽略过期响应；不每秒轮询。隐藏、销毁、离开权限页后停止自动查询。焦点回调表示重新检查的时机，不是授权成功回调。

### 用户确认重启

移除四秒倒计时。复用 relaunch 能力，并在调用前保存 onboarding 步骤和返回位置。若设置有未保存更改，使用现有保存/放弃/取消语义处理；保存失败不能继续重启。重启后返回发起授权的权限页面或引导第三步，首次引导“完成”仍可独立退出且不强制授权。

连续点击只发起一次重启。失败时显示可理解的错误并允许重试。用户只是返回窗口时不得自动重启，也不得宣称已检测到授权成功。

## Evidence and Limits

- Apple 官方流程为开启已有条目或通过加号添加：https://support.apple.com/guide/mac-help/allow-accessibility-apps-to-access-your-mac-mh43185/26/mac/26
- PermissionFlow 展示浮动拖拽引导这一实现形式，不代表市场普遍采用，也不证明 UU 的内部实现：https://github.com/jaywcjlove/PermissionFlow
- FIPLAB 指引包含授权后重启，可作为用户主动重启的参考：https://support.fiplab.com/getting-started/accessibility-permissions
- 原生拖拽须在项目支持的 macOS 版本上实测。不得通过自动点击开关或依赖尚未获得的辅助功能权限完成引导。

## Acceptance

重点测试“系统已授权、当前进程仍报告 required”路径：用户始终可手动重启，重启后独立查询。另测试未实际授权就返回、已就绪再进入配置、撤销权限、关闭引导、窗口隐藏、检测失败、未保存设置、重启失败及真实文件拖入系统设置。没有授权时仍可完成 onboarding 并手动粘贴。
