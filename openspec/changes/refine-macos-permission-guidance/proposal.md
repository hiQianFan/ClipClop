## Why

权限页面常驻“当前 App”、路径与旧条目说明，增加普通授权流程的阅读负担。现有重启逻辑只有检测到 permission_required → ready 且窗口重新获得焦点后才启动倒计时；当进程仍报告旧权限状态时，用户既无法刷新成功，也无法触发重启。倒计时重启还可能打断未保存的设置。

本提案等待用户确认后实施。此前固定自签名方案保持不变；本次解决授权引导与重启入口，不承诺刷新一定能获取系统设置中的最新开关状态，也不把所有 macOS 授权变化概括为必然需要重启。

## What Changes

- 删除设置页常驻的“当前 App”、路径、访达按钮及旧条目说明。
- 设置权限页与快速入门第三步复用相同的权限引导与状态规则。
- 点击授权入口打开对应系统设置，并展示轻量、可关闭的独立引导窗口，提供真实 App 文件拖拽及键盘替代路径。
- 提示已有条目直接开启；没有条目时拖入 ClipClop 并开启。拖拽结束不等于授权成功。
- 用户从授权流程返回后，原权限状态按钮所在位置显示“重启应用”；提示“如果已在系统设置中开启 ClipClop，请重新启动应用。”不要求先检测到 ready。
- 由用户点击重启，无倒计时、无自动重启。重启后重新检测并恢复正常状态按钮。
- 刷新保留为 RefreshCw 图标按钮，提供 tooltip 与 aria-label“刷新状态”。
- 完全磁盘访问复用引导窗口，但不显示未经验证的“已就绪”。

## Capabilities

### New Capabilities

- `macos-permission-guidance`: 授权引导窗口、用户确认重启、状态刷新和跨入口一致性。

## Impact

- 涉及 PermissionSettings、OnboardingView、现有 onboarding/settings IPC、process relaunch、原生窗口与文件拖拽、翻译和行为测试。
- 复用现有按钮、工具栏、设计 token、Lucide 和重启能力；复杂 Web 控件采用 Bits UI。
- Windows 不增加 macOS 权限入口；不修改签名身份、TCC 数据库，不执行权限重置命令。
- 不提交或发布安装包；实现须在提案获确认后开始。
